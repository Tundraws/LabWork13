# Code Review

## Проверка требований

- Исходный код расположен в `src/`.
- Тесты расположены в `tests/` и запускаются без внешней инфраструктуры.
- Есть `README.md`, `PROMPT_LOG.md`, `.gitignore`, `.env.example`, `docker-compose.yml`.
- Коммиты оформлены в стиле Conventional Commits.
- Go-агент имеет тонкий `main`, централизованную конфигурацию, graceful shutdown и dependency injection.
- Python API использует FastAPI lifespan, Pydantic-схемы, service layer и fake-шину для тестов.
- NATS используется как брокер сообщений между оркестратором и агентами.
- Redis используется для состояния агентов.
- Jaeger/OpenTelemetry добавлены для трассировки.
- Dashboard показывает события pipeline и действия агентов.

## Найденные риски и решения

- Локальная LLM может быть недоступна на компьютере проверяющего. Решение: LLM-ready советник реализован с детерминированным offline fallback.
- Unit-тесты не должны требовать NATS/Redis/Docker. Решение: добавлен `FakeNATSGateway`.
- Аукционное распределение не должно быть только имитацией. Решение: оркестратор собирает bid-ответы и выбирает победителя по стоимости.

## Остаточные ограничения

- Полный integration run требует Docker Desktop и свободные порты `4222`, `8000`, `8222`, `16686`.
- Нагрузочное масштабирование демонстрируется через `docker compose up --scale`, без отдельного autoscaler-сервиса.
